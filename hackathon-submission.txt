THE PROJECT
Project name: iTanongMo
Short description: A Filipino Freedom of Information request and agency workflow platform with human-reviewed AI assistance.
Team name: Balby
Team members: John Andrew Balbarosa
GitHub repository: https://github.com/JohnAndrewBalbarosa/iTanongMo-AppBuildersPH-Hackathon
Hardware tested on: Windows computer with Chrome for the recorded frontend showcase. Exact device specifications and phone or NPU benchmarks are not documented.

Project description:
iTanongMo helps Filipino citizens submit Freedom of Information requests to multiple agencies, track each request, receive public responses and documents, and file appeals. Government personnel use an agency-scoped board to review, route, and respond to requests with audit trails and deadline tracking. Deterministic rules flag requests for review, while optional AI tools provide draft assistance that a person must check and approve. A browser-based local classifier pilot processes request text on the reviewer's device; its suggestions are advisory and are not yet calibrated for Filipino or Taglish FOI requests.

THE DISCLOSURES
Models used: The optional browser-based triage pilot uses pinned multilingual MiniLM zero-shot ONNX through Transformers.js and ONNX Runtime Web. A separate CPU-only mDeBERTa experiment is not connected to the Rust service. Requester drafting uses Google Gemini 2.5 Flash with the requester's own API key. Government-only Qwen3-4B through Modal/vLLM is an optional integration and remains unvalidated for pilot use. A project-trained JEB checkpoint, Filipino/Taglish evaluation, calibrated thresholds, native phone companion, and NPU acceleration are future work.
Technologies and frameworks: Rust, Axum, Tokio, SQLx, SQLite, static HTML/CSS/JavaScript, Transformers.js, and ONNX Runtime Web.
APIs and cloud services: GitHub Pages hosts the frontend. The Rust JSON API supports submissions, tracking, agency workflows, and appeals. Google Gemini is called directly from the browser when requester drafting is enabled. Modal is an optional private government AI provider. The deployment configuration includes a VPS with HTTPS.
What runs locally: The Rust API and SQLite database can run locally, alongside a static frontend preview. After the first model download, browser triage inference runs on the reviewer's device through WebAssembly/CPU.
What requires internet: The first classifier download, hosted frontend and API access, Gemini drafting, and optional Modal AI. Browser classification processes request text locally; Gemini drafting sends draft details and the user-supplied API key directly to Google over HTTPS.
Existing code and assets: This hackathon repository continues work from an earlier iTanongMo workspace. The showcase uses synthetic cases and staged API responses; it does not demonstrate live agency participation.

LINKEDIN POST — ARCHITECTURE AND BERT-BASED TRIAGE GOAL
============================================================

Paano tutulungan ang FOI reviewers na makita agad ang mga request na maaaring kailangan ng mas maagang atensyon, nang hindi ipinapasa sa AI ang opisyal na desisyon?

Iyan ang goal ko sa iTanongMo. May citizen portal para magsumite at sumubaybay ng FOI requests, at may agency-scoped work board para sa government reviewers. Nasa GitHub Pages ang static frontend; Rust/Axum at SQLite ang API at workflow backend. Ang agency staff pa rin ang nagre-review, nagro-route, at nagpapadala ng opisyal na tugon.

Sa kasalukuyang triage flow, deterministic rules ang nagfa-flag ng posibleng time-sensitive, safety-related, sensitive-data, appeal, at iba pang cases. Nananatili sa ordinary queue ang mga hindi na-flag. May optional local classifier pilot din: pinned multilingual MiniLM ONNX ang nagbibigay ng category suggestions sa browser gamit ang WebAssembly/CPU. Hindi awtomatikong nase-save o nagiging desisyon ang model output; reviewer ang kailangang pumili at mag-confirm.

Ang susunod kong integration goal ay isang FOI-focused, BERT-based JEB classification harness:
1. Gumawa ng labeled Filipino, English, at Taglish FOI examples at sukatin ang recall, false positives, at latency.
2. I-export ang validated model at tokenizer para sa local browser inference, at i-version ang label map at thresholds.
3. Ipakita ang model suggestions kasama ng rule flags at mga deadline sa agency board. Ang priority view ay reviewer aid; hindi nito itatago ang ibang requests.
4. I-record ang human confirmation o correction bago makaapekto ang triage sa routing. Mananatiling server-side ang agency authorization at audit trail.

Privacy ang isang dahilan sa local inference: pagkatapos ng unang model download, sa reviewer device mapoproseso ang request text para sa classifier. Kailangan pa ring patunayan ang Filipino/Taglish accuracy at performance bago ito asahan sa operational workflow. Wala pang validated custom JEB checkpoint o phone NPU benchmark.

============================================================

Sa 90-second iTanongMo showcase na ito, makikita ang citizen FOI request flow, agency work board, routing, government response, at status timeline. Ang screen captures ay mula sa aktuwal na frontend, gamit ang synthetic requests at staged API responses para sa recording. Hindi ito live government transaction o patunay ng agency participation.

Goal ko para sa susunod na iteration ang FOI-focused JEB model at BERT-based local triage harness. Target nitong makatulong sa reviewers na makita ang mga request na maaaring time-sensitive o kailangan ng espesyal na review, kasabay ng deadline at rule flags. Reviewer pa rin ang magko-confirm ng classification at opisyal na aksyon. Kailangan pa ng labeled Filipino/Taglish evaluation at device testing bago ito gamitin bilang operational priority aid.
